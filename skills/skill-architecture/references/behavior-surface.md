# 实际塑造行为的系统

## 为什么不能从声明重建
仓库用 README、名称、目录结构和注释描述意图。行为不由意图决定，而由四件事决定：什么被加载、什么被门控、什么被消费、什么被持久化。

意图与实际之间的偏差不是疏忽，而是这类系统的常态：文档的更新成本高于提示与代码，且没有人会因为文档过期而失败。所以重建的起点不是「这个 Skill 声称做什么」，而是「模型在这个位置实际看到什么、被要求填什么、不能做什么、能记住什么」。

## 行为面清册
- **description / frontmatter**：触发面。它决定这个 Skill 何时存在。措辞是行为，不是文档；过窄等于不存在，过宽会吞掉不属于它的任务。description 只承担触发与边界区分；领域事实、规则和流程不放入，除非它直接改变触发。
- **常驻正文 与 条件加载的 reference**：reference 索引实际是上下文加载策略。「需要时读取」意味着多数时候不读取；一件被声明为关键、却放在条件引用里的知识，可能从未到达模型。拆分单位是任务与真实消费者，不是文档目录完整性；没有条件加载场景和读取者的 reference，只是被推迟的正文。
- **Router / 派发谓词**：真实边界是派发条件，不是目录结构。两个 Skill 共享同一派发条件时，它们不是两个边界。
- **模板 / 必填章节 / 产物 schema**：输出强制。会被填写的东西会反向影响调查方向；结构越完整，越容易被当成「分析必须覆盖的范围」。
- **Validator / 脚本 / 门 / 回归测试**：检查真实拒绝条件与调用路径。未检查的内容不能声称由机器保证，但仍可能被 Prompt 强制；测试可能只冻结历史表达，不能因它通过就认定设计正确。
- **State / registry / workspace 协议 / 缓存**：跨上下文的记忆，也是「当前相信什么」的实际权威。恢复时模型相信状态文件，而不是正文。
- **Tool / 权限边界**：能力面。模型能做什么在物理上由工具决定；「不要这样做」的提示弱于「没有这个工具」。
- **错误与恢复路径**：失败后能否继续、是否留下可修正的痕迹，决定这个系统在真实使用中收敛还是崩坏。
- **指令的组合**：不只是约束相加。Router 的适用范围、Reference 的例外、模板必填和 Validator 的拒绝条件可能互相封死或冲突；沿同一任务的实际加载与消费关系看合成约束。

## 重建要建立的事实
- 每类产物的真实消费者是谁：模型自己、另一个 Skill、机器、人，还是没有人。
- 「当前事实」的单一权威在哪里；同一事实是否有多处签发。
- 哪些机制真的运行过。存在不等于使用；有调用、有写回、有事故记录才算。
- fresh context 下能恢复什么：只读状态文件能否重建理解，还是只能重建进度。
- 删除后会失去什么事实、保护或判断支持。没有解析器不等于没有模型或人类读者，现有测试不失败也不证明知识可删。

重建不是把仓库读完。沿消费者走：从一个产物的写入点走到读取点，比通读全部文件更能暴露真实结构。

## 声明与实际的典型落差
- 声称独立评审，实际仍读取实现者的上下文与产物——名义独立。
- 声称是知识层，实际被无条件加载，因此是常驻提示——reference 已成为正文。
- 声称是约束，实际无人消费、无执行路径——死机制。
- 声称是兼容，实际没有旧资产也没有退出条件——长期双轨。
- 声称是保障，实际把不确定性转成治理面——registry 化。

## 产物是事实，不是边界
重建产生的是当前现实。它说明系统现在如何工作，不说明它必须这样工作。现有 IA、模块划分、页面、流程都是证据；诊断范围可以超出当前实现范围。

但改变现状同样需要证据：现有结构不是设计约束，「更合理」也不是变更理由。两类错误对称——把现实当边界，和把现实当错误。
