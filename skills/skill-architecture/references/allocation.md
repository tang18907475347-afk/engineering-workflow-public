# 责任分配
审计的单位通常是一个具体机制：一个 reference、一条必填章节、一个 validator、一个 state 文件、一次拆分、一层兼容。问题不是它复杂不复杂，而是它承担的是确定性负担还是判断负担，以及有没有真实消费者。

以下按机制类型组织。这些单元是判断对象，不是检查表：只取用与手上机制对应的那一节。

这里只写判断标准，不写实例。真实发生过的失败按机制命名记录在 [observed-failures.md](observed-failures.md)，从那边的症状进入通常更快。

## 一个机制值得保留的条件
保留理由应指向当前真实消费者或故障：承担模型难以可靠获得、维持或安全执行的内容，或有证据支持的判断辅助价值；约束范围不超过依据。单项有价值不证明组合后仍有净收益，原先必要也不证明现在仍需保留。

复杂不是理由，简洁也不是。

## 身份与边界
**可承担**：真实的加载差异、工具或权限差异、状态差异、独立用户意图、稳定责任边界。Router 作为派发谓词是合理形态。

**同时要付代价**：拆分制造交接、重复理解与上下文损失。只有独立性本身带来真实价值时，这个成本才值得支付；一个能力有价值，不代表它必须成为独立 Skill。

**越界信号**：把生命周期阶段、作用范围（System / Module / Page）、变化幅度（Optimize / Redesign / Reimagine）、文件类型，或者「可以被描述成一项职责」直接当成 Skill identity。

**所需证据**：拆分是否真的改变了加载、权限、上下文或责任归属；`description` 是否真的改变了触发；被假设的独立判断是否真的独立。Skill 身份本身不产生上下文隔离，这是最常见的假证据。

## 知识
**可承担**：外部事实、来源、可信状态、未知项、权限、工具与领域契约、恢复信息，以及非显然的领域经验。经验作为可选择的判断依据；固化为过程需要相称的确定性要求或故障依据，而不是因为曾有用就强制每次执行。知识应说明现在相信什么、依据与适用范围，并能被新证据修正或替换。

**越界信号**：把调查顺序、诊断方法、决策流程写成知识；把分析框架当成外化；同一事实有多处签发；历史产物只增不修。

**所需证据**：谁在读它、读后改变了什么行为；同一当前事实是否只有一个权威；新证据出现时有没有明确的修正路径。

## 结构与流程
**可承担**：服务机器、协作者或人类读者的产物结构；路径已知的确定性转换；跨轮次恢复信息。稳定到消费者真正依赖的部分，不把格式、章节或独立文件的存在当作理解完成。

**越界信号**：为填满章节而调查，结构变成推理顺序；固定调查计划做成硬门；把「走到第几步」当成理解；问题结构尚未知却预设完整流程；把固定步骤包装成 Loop；多条流程叠加后模型没有剩余判断空间。

**所需证据**：结构的消费者是谁；固定顺序是外部契约还是假设；循环里沉淀的是可修正知识还是执行记录。

**一条区分**：路径已知的确定性转换适合流水线；问题分解需要在执行中发现的任务，适合让模型基于最新可信知识决定下一步，并把理解沉淀在可修正的外部状态里。二者可以组合，但组合顺序不应由流程规定。

## 控制与校验
**可承担**：机器可判定的事物——格式、schema、权限、状态完整性、幂等、外部契约。这类约束越硬越省事，因为模型不必猜测。

**越界信号**：它拒绝的事物无法由机器判定；没有机器消费者却要求强制通过；多条单看合理的规则叠加后整体压缩判断空间。工具同理：把需要判断的步骤做成脚本或工具，工具输出会取代判断。

**所需证据**：谁消费校验结果；拒绝的是机器事实还是判断；例外是否被其他层封死。测试应保护可观察行为、授权与机器接口，不以逐字匹配历史 Prompt、中文措辞或章节顺序证明架构正确；只有真实消费者依赖的文本才是格式契约。

**诊断型校验**：供 Agent 消费的 validator / linter 应优化完整诊断效率，而不是首次失败的响应速度。能够独立检查的问题应在一次执行中聚合报告；某项因前置数据无效无法继续时，跳过该项并说明原因，不阻止其他独立检查；只有无法读取核心输入、继续会产生错误诊断或危险副作用时才提前终止。聚合不改变退出码语义：有问题仍返回非零，报告包含问题类型、位置与原因。不可逆写操作（上传、发布、迁移）不属于此原则，仍应失败即停。

## 状态与恢复
**可承担**：跨上下文必须相信的东西——当前结论、来源、未知项、未完成决策、外部副作用记录、恢复所需的最小事实。状态的价值在于让 fresh context 重建理解并纠错。

**越界信号**：每发现问题就增加 Registry / State，把不确定性治理化；记录执行进度而不是理解；同一事实多处写；状态写了没有读取者，或者没有退出条件。

**所需证据**：谁读回它；fresh context 下它是否真的恢复理解；它解决的是确定性需求，还是把不确定性转成了治理复杂度。

## 分布与兼容
**可承担**：有稳定共同消费者的语义正本；有现实对象和可识别退出条件的兼容层。

**越界信号**：为少量重复建立中央共享层；共享 reference 逐步演化成运行时耦合与中央治理；兼容层没有现实旧资产，或没有停用条件。

**所需证据**：跨域是否真的需要同一语义与约束，还是仅概念相似；生成副本能否明确指回编辑源，且不自称另一权威。局部 schema 不因进入 shared 就成为全局协议；收窄适用范围不等于删除领域内真实消费的契约。兼容仍需现实对象与退出条件。

以上各节描述的是机制类型层面的判断标准。真实失败不按这些类目组织——它按「人先注意到什么」出现，记录在 [observed-failures.md](observed-failures.md)。
