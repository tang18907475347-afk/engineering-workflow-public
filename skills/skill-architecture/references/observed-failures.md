# 已观察到的失败
这里记录的是真实 Skill / Plugin 设计与审计中已经发生过的失败：它长什么样、代价是什么、这个解释在什么范围内成立。

它不是设计原则的另一份写法。原则——各类机制如何起作用、能承担什么、需要什么证据——在 [allocation.md](allocation.md) 与 [evidence-and-scale.md](evidence-and-scale.md)。这里只保留从原则推不出来的东西：真实出现的形态，以及这些形态出现时的具体条件。

也不是检查表。不要从第一条开始核对；人通常是因为已经看到某处不对才来这里。下面的机制是当前最好的解释，不是自动裁决：同样的表象可能是合理复杂性，判定仍取决于该仓库的真实消费者、失败影响、权限与外部副作用、状态需求、替代成本和行为证据。

## 能力边界建模错误
**机制**：把生命周期阶段、作用范围、变化尺度、可描述职责这些组织维度，或 Skill 身份本身，误当成稳定能力边界与价值来源——没有验证该形式是否真实产生所要的能力、隔离或上下文价值，就据此切分或保留结构。
**实际发生**：每个生命周期阶段一个 Skill；System / Module 拆成独立 Skill；Optimize / Redesign / Reimagine 拆成独立 Skill；每个可描述职责都独立成 Skill；为「大改 / 小改」预先建立流程模式；独立 Review Skill 仍共享实现者上下文与产物。
**它不解释**：切分数量本身。存在真实加载、权限、状态或独立用户意图差异时，这条不适用；它针对的是边界由组织维度构成，而不是边界多。

## 确定性与判断错位
**机制**：把概率性判断工作交给确定性结构承担或指挥——流程替代判断、产物结构规定调查顺序、校验器裁决语义；或多条局部合理的控制叠加后，整体压缩判断空间。
**实际发生**：缺陷调查同时受搜索计数、预侦察分流、依赖源码禁令与续写许可约束；工程计划固定章节与回源限制叠加，参考驱动设计却要求先独立合成。另有可复现误判：无 UI 的 Baseline 被要求填体验表；“无需人工验收”因命中关键词被判需人工；回归测试逐字断言中文 Prompt，使合理改写也失败。
**它不解释**：有流程这件事。路径已知、有外部契约或机器消费者的流程不属于此；判据是该结构管辖的是机器事实还是判断。

## 无证据机制
**机制**：以完整性、理论自洽或形式收束为理由引入校验器、状态、字段、规则与文档机制，而真实证据缺位——没有消费者、没有失败案例、没有行为对照。材料越来越完整，行为价值没有增加。
**实际发生**：没有机器消费者却新增校验器；规则存在但无消费者、无执行路径；为理论完整性增加字段、状态、阶段；文档越来越完整，模型效果反而更差。
**它不解释**：机制复杂。有真实事故、外部契约、机器消费者或权限风险的机制不适用；这类机制需要的通常不是删减。

## 去重驱动的过度中央化
**机制**：以「存在重复」为由建立中央共享层；当重复没有造成真实错误、共同消费者又不稳定时，耦合、加载与分发成本超过去重收益，共享引用逐步演化成运行时耦合与中央治理。
**实际发生**：领域内的八列证据表与 ID 唯一性被推广到设计、实施和模块记录，但校验器只覆盖产品知识域；跨域使用者因此承担没有对应校验的全局登记义务。概念相似被当成相同消费者需求。
**它不解释**：中央化本身。重复是否真的导致过错误、共同消费者是否稳定，才是判据；已经产生真实漂移的重复不属于此。

## 兼容没有退出条件
**机制**：兼容层为真实旧资产建立后，没有可识别的退出条件，新旧语义长期双轨——迁移成本被永久化，历史兼容反而阻断彻底切换。
**实际发生**：临时双读长期存在；新旧语义长期并行，无人能说何时停用。
**它不解释**：兼容应该删除。有现实旧资产与明确退出条件的兼容不适用；它针对的是没有对象或没有退出路径的兼容。

## 当前事实缺少权威与修正
**机制**：同一事实或 token 有多个生产者、多处签发，或历史产物只增不修——缺少单一当前权威与修正路径，恢复与纠错时无法判断「当前相信什么」。
**实际发生**：同一 token / truth 在多处签发；历史文档只增不修；生成副本头部禁止编辑，复制来的正文却自称唯一编辑源并要求修改“本文件”。
**它不解释**：同一主题出现在多处。索引与正文、摘要与展开、原则与实例覆盖同一主题，但都不独立定义同一句当前事实；判据是两处是否都能各自改写同一个判断。

## 当前现实被固化为设计边界
**机制**：把现有 IA / Module / Page / 流程直接当作设计约束——现实与设计混层；当前实现是事实证据，不是未来边界。
**实际发生**：现有 IA / Module / Page 直接变成设计约束，诊断在模块边界处停止。
**它不解释**：现状应该被推翻。它只说明现状不构成约束；是否改变仍要由根因证据决定。

## 问题响应不收敛
**机制**：对暴露问题的默认响应是就地增加——补丁、状态、治理——而不是检验底层模型与根因。变更与根因错配，失败复发或治理面持续膨胀。
**实际发生**：每次只修暴露问题，没有挑战底层模型；每发现问题就增加 Registry / State，把不确定性变成治理复杂度。
**它不解释**：所有新增。外部契约扩张、事故边界变化带来的结构增长不属于此；判据是新增对应的是确定性需求，还是把不确定性治理化了。
