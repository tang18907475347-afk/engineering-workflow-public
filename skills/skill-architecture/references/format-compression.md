# 表达压缩
审计可以得出「架构保持，仅压缩表达」。这不是格式规范检查，也不是默认收尾动作；它只在知识、权威与门控已经成立，而真实读取成本来自不承载语义的空白、重复或分段时成立。行数不是质量指标，压缩也不是审计结论的默认形态。

## 什么时候成立
- 真实问题是读取成本：标题后空行、短代码块、同主题短段、重复摘要、无消费者的复述。
- 真实问题不是知识缺失、责任错配、门控失效或权威冲突；这些必须走结构修正，不能靠删空行掩盖。
- 目标文件有明确消费者；压缩不会改变脚本、validator、模板或人工消费者的解析结果。
- 压缩后至少不降低可读性与可维护性；如果只是把可扫读的结构压成墙，属于负向压缩。

## 可压
- 删除标题后、短列表前、短代码块前后不承载语义的空行。代码块前后若承担扫读边界，保留一个空行；压缩不是删光空行。
- 合并被硬换行拆开的同一段；合并同一规则的同主题短段，但保留规则边界。
- 单行、非复制执行的符号签名或短表达式可改为 inline code；长命令、可复制命令、配置与模板保持代码块。
- 删除同一事实的重复摘要，保留唯一权威表述；重复只允许存在于生成副本，不允许手工双写。
- 表格压掉 cell 边缘 padding，并把分隔行压到最小合法宽度（保留 `:` 对齐）；表格承载对照关系时保留结构，不把行改成散文。

## 不可压
- 硬门禁、停止条件、权限边界、状态语义、反例、真实失败经验与适用范围。
- 会被脚本、validator、模板或机器消费者解析的格式、字段、标题、ID、链接与代码块。
- 复制即执行的命令、完整配置、JSON / YAML / Markdown 模板与输出骨架。
- 生成副本（如 `references/*.md` 由 `shared/*.md` 生成）；要改就改唯一源并重新生成。
- 为了达到行数目标而删除 nuance、合并不同规则、把门禁改写成叙述、或删除承载事故经验的例子。

## 流程
1. **盘点**：区分 authored / generated、entry / reference / template / asset；确认每个候选的真实消费者。宿主若会在保存时自动格式化目标语言，先关闭该语言的 `formatOnSave`，否则压缩结果会被回填。
2. **基线**：记录行数、空行率、短代码块数、链接目标、代码块配平、frontmatter；保存词项多重集。
3. **分类**：把空白与分段分为结构性与语义性；列出受保护文件与受保护区块。
4. **压缩**：逐文件执行可压操作；不改写规则，不调整章节顺序，不新增解释。模板与生成副本不进入本轮。
5. **验证**：词项多重集只允许减少空白或获批的 fence 标记；链接目标、代码块配平、frontmatter、脚本入口不变；运行仓库测试与插件检查；逐文件看 diff。
6. **裁决**：语义有新增/缺失、链接断裂、模板变化、测试失败或可读性明显下降 → 回退。行数下降但收益很小、可读性变差 → 保留原样。

## 证据边界
词项对比、链接检查、fence 配平与测试通过，能证明「没有丢失文本、没有破坏已知消费者」，不能证明「模型行为不变」。后者需要行为对照，不能由行数或静态检查替代。若格式本身就是机器契约，把它当作受保护内容，而不是压缩对象。

## 报告
逐文件报告 before / after 行数、空行率、验证结果与残留风险；明确列出未压文件及原因。只有同时满足「语义未变、消费者未变、可读性未降」才称为正向压缩；不要用总行数下降替代这个判断。

## 停止
候选文件处理完，或剩余文件都是受保护的模板 / 生成副本 / 高密度规则时停止。不同 Skill 允许不同密度；不要求为了统一而继续压缩。
