# Skill Architecture
判断对象是已经存在的 Skill / Plugin 及其引用体系。要回答三件事：**它实际是什么**——哪些机制真正塑造模型行为；**责任分配是否合理**——知识、工具、状态、权限、流程与模型判断各承担了什么；**该改变多少**——保持、局部修正还是结构性重构。reference 按这三件事和症状反查组织，缺什么读什么，不要按顺序走完再判断。

## 声明不是架构
README、Skill 名称、目录结构、作者声明的职责都只是意图。真实架构由实际加载、实际门控、实际消费、实际持久化的东西构成：`description` 决定何时触发，reference 索引决定知识是否真的到达，模板决定模型必须填什么，validator 决定什么不能通过，state 决定跨上下文相信什么，router 的派发谓词决定真实边界，多条独立规则共同决定实际的约束强度。先重建行为面，再评价设计；不要用文档描述替代行为证据。

重建的产物是当前现实。当前实现是证据，说明系统现在如何工作，不说明它必须这样工作；诊断范围可以超出当前实现范围。

## 不预设尺度
复杂性本身不是缺陷，也不是优点。保留理由来自当前消费者、外部副作用、状态与恢复、权限风险及行为结果，不是机制最初为何建立。架构质量也取决于能否淘汰不再产生净收益的机制；保持、删除与重构都由根因和证据支撑，不预设越少或越复杂越好。

所以不要在确立根因之前选择尺度。不因为「重构更彻底」而重建，也不因为「改动更小」而打补丁；规模是结论，不是目标。

## 谁承担什么
系统适合承接模型难以自行获得或长期维持的东西：外部系统事实、来源与当前可信状态、工具行为、权限、确定性状态、恢复信息、机器消费者要求的格式。诊断、综合、权衡、根因判断、架构判断、设计判断属于模型，不应因为它们困难就被替换成流程、清单或校验。硬控制只覆盖机器可判定的事物——格式、权限、状态完整性、确定性契约；语义真伪、根因和设计优劣不能由校验器裁决。

产物结构服务消费者与恢复，不应反过来定义问题或调查顺序。领域经验可支持判断，不自动成为固定步骤、搜索预算或评分门槛；强制过程需要相称的确定性要求、外部约束或真实故障依据。路径已知的转换适合流水线；问题结构尚待发现时，模型应能基于最新可信知识选择下一步。评估各层组合后的约束，而不只逐条论证合理性。

## 张力与偏好
设计张力允许长期存在。统一与自包含、稳定结构与自适应判断、独立上下文与连续理解、兼容与简洁，都可能同时保护真实价值；不要为了理论一致消灭一边。必须消除的是同一作用域下同一当前事实的多个权威生产者——那是语义矛盾，不是张力。

用户偏好可以约束当前项目的取舍，但不构成通用设计事实，也不应被复述成设计原则。

## 静态证据的边界
能裁定的与不能裁定的不是同一类问题。结构事实——权威归属、消费者是否存在、门控是否成立、状态是否重复、退出条件是否缺失、多条规则组合后的实际约束——通常可以由材料本身裁决。行为效果——是否优于裸模型、清单是否压制了判断、fresh context 是否真的隔离、缓存是否有净收益、循环是否长期收敛——不能。

后者必须停在「需要行为验证」，并说明需要什么对照才能裁决。不要用理论补全，也不要把它写成确定结论。审计在剩余不确定性只能由真实行为解决时结束，而不是在仓库被读完时结束。

## 结果应能回答
报告形式自由，但应能回答：目标系统实际是什么；哪些复杂性在承担真实负担，哪些在制造成本或压制判断；关键边界与权威是否成立；哪些改动有足够证据、属于哪一等；哪些问题必须交给行为验证；在证据不足时什么不应该被增加。

不必覆盖全部方面。没有发现问题的方面不需要制造结论，也不要为了让报告完整而新增没有判断支撑的章节。

## 表达成本
格式压缩不是规范符合性检查，也不是默认动作。只有当审计确认知识、权威与门控成立，而真实读取成本来自空行、短代码块、重复摘要或同主题分段时，才把「仅压缩表达」作为结论。压缩只允许删除不承载语义的空白与重复，不得改动规则、边界、反例、失败经验、硬门禁、命令、模板或机器消费者格式。

必须证明语义未变：词项对比无新增或缺失、链接与代码块完整、测试与插件检查通过；行数下降本身不是质量证据。具体流程、可压 / 不可压边界与验证证据见 [references/format-compression.md](references/format-compression.md)。
