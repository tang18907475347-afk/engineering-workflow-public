# 产品资料阅读参考

## 先建立整体，不按文件逐份复述
读取 PRD、设计稿和素材后，先回答：产品目标是什么 / 有哪些核心模块 / 用户从哪里进入并完成目标 / 哪些规则跨模块生效。输出应按产品理解重组，而不是按输入文件顺序复述。

## PRD
优先提取：目标、范围、业务规则、操作结果、生命周期、异常恢复、明确限制。历史描述、背景说明、实现建议只有在影响当前交互时进入澄清文档。

## 设计稿
优先观察：入口、页面层级、可操作项、默认/空/加载/成功/失败等状态、按钮与返回关系、弹窗确认、设计中真实可见但 PRD 未展开的交互。

不要因为设计稿“看得到”就自动认定它比 PRD 更新；也不要因为 PRD 有文字就忽略设计稿表现出的真实差异。

## 静态素材
素材用于补充实际内容、示例、状态和视觉上下文。只有当素材改变需求/交互理解时才写入主体；纯装饰素材不需要逐项说明。

## 同一事实的多来源处理
1. 语义一致、表达不同：合并成一个清晰结论。
2. 一个来源更详细、另一个没有冲突：采用更完整描述，不制造分歧。
3. 两个来源无法同时成立：先核对版本和上下文；会改变交互、结果或实现的，保留问题及后果，只合并同一决策的重复症状，并在问题下给有依据的分析或建议。
4. 上下文足以判断一个来源明显是旧稿/占位内容：可以给出「当前理解」，同时简短说明判断依据。
5. 无法可靠判断：不同选择会造成实质不同结果时，保留在问题清单并在问题下面写 AI 分析/建议；模型推荐某个方向也不能替用户关闭该问题。确需产品或设计选择时，明确写出待决定事项。纯表达或展示、且不改变用户或业务结果的差异可合并说明。

## 格式信号即语义
资料的排版 / 图层信号常直接承载需求语义，不能只读正文文字——这是**识别信号、不是逐项必扫的清单**，只在资料真出现时判定，必要时回源逐字核对（如 grep 删除线标记），别凭上下文感觉：
- **PRD 编辑痕迹**：删除线、批注色、「历史 / 废弃 / v1」章节、同一对象并存的两套表。先判定其**效力**——移出本次范围 / 废弃、沿用线上既有规则、还是没搬完的缺口，并把判定依据写进「当前理解」。**但若被删或旧稿规则是当前主链的必要环节（状态回填、不可逆动作后果、错误修复路径），必须作为缺失风险列出，不能静默丢弃。**
- **设计稿大纲 / 标注**：字段计数文本（`0/50`、`142/150`）、必填标记 `*`、按钮文案、状态标签（「安审失败」「默认技能」）、空态文案、`hidden` 图层、同名不同 node-id 的多版稿——可能承载数值级 / 状态级规格。与 PRD 字段规则对照后，先核对版本和上下文；差异确实改变校验、状态或用户结果时必须保留为问题，并在问题下面写 AI 分析/建议，不能因某一来源看起来更可信就沉入正文。截图看不清的小字回 `get_metadata` 大纲或节点原文核对（`fetch_figma_design.py` 已注明「大纲只是布局辅助，文本全文需回源或看截图」）。

## 设计稿图片
如果图片能显著降低理解成本，优先选择能代表关键状态或关键差异的少量截图。一个流程不需要为每一步都配图；同类视图优先选最有信息量的一张。

## 阅读优先级
先核心主链，再影响主链的状态/规则，再异常恢复，最后才是低影响细节。不要因为资料多就把所有信息等权展开。
