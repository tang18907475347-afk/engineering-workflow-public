# Environment Boundary — 前置依赖与环境阻断分流
本文件是采集层的环境边界权威：把「技能要完成的工作」与「运行技能所需环境」分开，不替代任何输入、推理或产物契约。

## 三类情况
|情况|典型证据|默认动作|
|---|---|---|
|输入产物未就绪|PRD 源料或 Figma 资产尚未生成，但工具可用|按上游路由补齐输入；补齐后回到原请求继续，不要求用户重发指令|
|执行环境阻断|平台客户端不存在、Figma MCP 未启动、`FIGMA_TOKEN` 缺失/失效、认证过期、权限不足、Python 依赖缺失、非 git worktree、目标路径不可访问|停止当前原子及下游，只做必要只读诊断，向用户报备；不把环境修复伪装成技能工作|
|产物或规则错误|工具可用但源料损坏、契约不满足、校验失败|在授权范围内修复源料/产物/规则并重跑校验；不借机改运行环境|

「输入未就绪」与「环境阻断」必须分开：缺 `sources/prd/<slug>.md` 可路由到 PRD 采集；平台客户端不存在、认证失效、Figma MCP 拒连、REST token 无效则不能自行安装/登录/启动服务来「补齐输入」。

## 环境阻断处理协议
1. 停止受阻原子和依赖它的下游；不生成半成品、伪造占位事实或「已通过」产物。
2. 只做能证明阻断原因的只读检查（命令是否存在、路径是否可读、服务能否握手、token 是否被拒）；不循环重试，不改 `PATH`/配置/权限/应用状态。
3. 向用户报四项：阻断步骤、原始错误/可复核证据、对当前请求的影响、可选恢复动作与恢复后的继续位置。
4. 用户未明确要求修环境时，不执行安装/认证/授权/启停应用/网络或权限修复；若明确要求，先当独立任务说明副作用再执行。

## 本技能的恢复选项
- 平台客户端不可用或认证/权限失败：用户恢复平台环境，或直接提供 PRD 文本；不代跑 `qp mcp auth`。
- Figma Dev Mode MCP 不可用：用户打开 Figma 桌面端并启用本地 MCP，或提供 `FIGMA_TOKEN` 走 REST 兜底，或直接给截图/已入库资产；不启动、安装或改 Figma 配置。
- REST token 缺失/401/403/429：用户提供有效 token 或稍后重试；不猜、不自动生成、不循环重试。
- 非 git worktree：采集脚本会 `[BLOCKED]`；用户在 git 仓库内运行（本工作区已 git init）。
- Python 不可用：用户补齐运行时；不自动安装解释器或依赖。

恢复后只从被阻断的原子重新开始；已通过校验的上游输入不重复重建，也不静默改变用户原请求。
