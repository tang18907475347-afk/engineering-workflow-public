# 澄清模式参考

## 1. 自动行为不要伪装成用户行为
资料：用户点击保存，保存成功后自动进入预览。

正确：
```text
编辑页 → 点击保存 → 保存成功 → 自动进入预览
```

避免：
```text
编辑页 → 点击保存 → 已保存 → 用户点击打开预览
```
除非资料真的存在第二次点击。

## 2. 同一去向不代表同一行为
两个操作都回到预览，但如果能力、结果、计费、资产变化或恢复方式不同，应分别说明；文档层不需要为此建立形式对象，只需不要把不同产品行为写成一句模糊的「执行操作」。

## 3. 临时弹窗也可能重要
「弹窗不是独立页面」不等于「可以忽略」。如果它承担确认放弃、提交、删除、取消任务等重要决定，应写进交互流程。

## 4. 成功路径不能替代失败路径
资料明确写了保存失败保留输入并重试，就需要在相关模块中说明。不要因为主流程能跑通就省略。

## 5. 资料冲突不静默选边
资料 A 和资料 B 给出不同结果，且两者无法同时成立：明确列分歧和影响。只有上下文足以解释时才给出「当前理解」。

## 6. 图片只做解释
截图用于说明入口、布局关系、状态差异或文案冲突。不要为「证据完整」堆图；只保留真正帮助理解交互的图片。

## 7. 不追求穷尽所有边界
优先交付主链、关键异常、真实冲突和会影响实现的缺失。低概率、低影响、资料未涉及的理论边界不主动扩写。
