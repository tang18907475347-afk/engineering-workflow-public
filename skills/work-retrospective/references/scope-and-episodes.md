# 范围与片段
> 范围由用户决定，片段由范围推出。这里只说明怎样把两者对应起来。

## 范围是查询
字段都是可选的，可以任意组合；没有给出的字段不设默认值。

```text
req       需求标识，对应 requirements/<req>/
task      任务或会话标识，或一句话描述
branch    分支名或 MR
window    时间窗口：[from, to]；也可以是“上周”“上个月”这类，由接入方换算成具体日期
project   工作目录或项目
text      用户用自然语言描述的事情
```
- 组合用“并且”：同时给 `window` 和 `project`，就是该项目在该时间段内的。
- 范围太大（例如整个月、多个项目）时，先给一屏概览，再问用户想深入哪几个片段，而不是一次铺开全部。
- 范围里没有任何数据时，直接说明并停止，不要用常识补一份复盘。

## 请求片段
**请求片段** = 用户提出的一个要求，加上为它所做的全部工作，直到这个要求的结果落地。它是分析的基本单位。

边界规则：
- **起点**：用户发出的、带有新目标的消息。只是追问、纠正、补充的消息不开新片段，它们属于当前片段，而且正是要找的信号。
- **终点**：结果落地的标志之一：合并或交付、用户确认完成、用户转向新目标、会话结束。
- 一个要求可能跨多个会话（先澄清，后实现），应合成一个片段，并在片段里记下经历了哪些会话。
- 一个会话可能含几个要求，应拆成几个片段。
- 边界不确定时，不要硬切。写成“边界不确定”，说明依据，让用户来定。

## 片段记录
```text
id            片段编号
ask           用户最初提出的要求（短摘要 + 证据指针）
scope_refs    关联的需求 / 分支 / 提交 / 会话
timeline      关键节点：提出 → 澄清 → 动手 → 纠正 → 交付，各带时间与证据指针
outcome       结果：已交付 / 被回滚 / 之后有修复 / 未完成 / 不明
signals       命中的偏离线索（线索，不是结论）
intent        明说的目标 / 隐含的目标 / 没说的约束（各带档位）
judgement     偏 | 反 | 未偏 | 无法判断
attribution   四侧归因（见 taxonomy.md）
kept          做对的地方
```

## 关联
把会话、需求、分支或提交连起来，用的是已有的键，不新造：
- 工作目录（cwd）加时间窗口，对应到分支和提交；
- `requirements/<req>/` 的目录名当作需求标识；
- 会话里引用的提交号、分支名、MR 号。
关联不上就写“未关联”，不要靠相似度猜。猜出来的关联，档位是“推断”。
