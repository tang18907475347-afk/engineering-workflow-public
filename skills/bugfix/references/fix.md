# 修复通道
输入为已确定需求快照的分析档案 `<req_id>/analyses/<bug_id>.md`，以及用户明确的修复意图。分析、提交和工单回写不是隐含授权。

## 接续当前方案
读档案的归属、完成度、档位、修复方案与验证边界。手动档或字段缺失时先核查实际阻塞；必要产品决定、依赖或根因尚未成立，不能靠执行阶段猜造。用户接受暂定结论不等于事实已证明。

档案 commit 与当前 Repo 不同是重新核验的线索，不是自动请示条件。核对相关源码、依赖、worktree 改动与证据；方案仍成立就继续，局部漂移原地更新。发现超出授权范围、关键语义未决或与用户改动冲突才停止该部分并说明。

档案证据用于定位，修改前仍确认当前内容。验证策略可随真实实现与可用环境调整，不盲从历史档位。

## 范围与实现
修到当前缺陷的根因闭合，调查共享机制实际消费者与同根因分支；不因 QA 只报一处就忽略必要修复，也不自动补齐整个交互域的无关问题。新发现的独立缺陷记录待处理，不顺手扩大授权。

已批准方案的必要条目不能静默删减或降级；确实需要改变产品行为、范围或验收时说明影响并请求决定。纯工程落点调整可自行判断并更新档案。多单元缺环时不声称整单 Fixed。

样式或交互修改关注实际宿主与事件链，例如壳 / input、hover / disabled 覆盖、焦点、IME；选择能证明目标行为的验证，不把 DOM 属性等价于实际视觉。

## 验证与交付
使用目标仓真实测试配置与入口，不假设 runner。可确定性复现的问题优先补能在未修复时失败、修复后通过的断言。检查失败原因，不能把红灯说成完成；既有失败与本次回归分开说明。

证据覆盖取决于实际工具、场景与条件，不采用固定病灶层或 cover 度公式。自动化浏览器、截图或真实链路可证明相应结果；mock 通过不能代替未观察的外部行为。缺失 runner / 账号 / 环境时记录实际缺口，只阻塞受影响的完成判断，不机械中止所有可执行修改。

用户要求的人工审阅、方案明确保留的人工 / 外部验收仍需满足。已经充分自动验证的结果不再强制人工复验，不要求每次输出分级清单；剩余人工义务需说明具体场景与预期。

把实际修改、验证覆盖与结果、剩余阻塞写回既有“执行结果”节，不另建执行记录体系。实际偏离分析判断时更新相关结论，Reopen 后仍能还原失效原因。报告完成范围，不以测试命令成功代替正确性声称。

修复交付后停止。仅用户明确要求提交时 commit；明确要求回写时另走 [triage.md](triage.md)。确认修复结果不自动授权这两项外部 / Git 动作。
