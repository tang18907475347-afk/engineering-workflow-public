# 提案：skill-architecture 补充“模型相对性”（草案，待作者审阅）

> 状态：草案。skill-architecture 按其 README 从独立来源同步，**本插件内的副本不做修改**。若采纳，请在独立来源中修改后再同步过来。
> 依据：Anthropic《Skill authoring best practices》写明 “Skills act as additions to models, so effectiveness depends on the underlying model. Test your Skill with all the models you plan to use it with”，并按任务脆弱程度区分高 / 中 / 低自由度；本插件在 flash 系列模型上的使用经验（判断类阶段需要更多支撑，编码类阶段不需要）。

## 为什么要补
现有框架回答了“一个机制该不该存在、由谁承担”，但默认了“判断属于模型”中的模型足够强。同一份判断辅助，对弱模型可能是必要的支撑，对强模型可能是束缚；不写明目标模型，就无法判断它的净收益，也解释不了“对强模型最优的写法在弱模型上产生摩擦”这类现象。

## 建议的三处补充（每处一段，措辞供参考）

**1. `references/allocation.md`「结构与流程」一节末尾**
> **净收益相对于目标模型。** 判断辅助（流程引导、清单、示例、默认做法）是否值得存在，取决于它服务的是哪个模型：对判断能力不足的模型，它可能是必要的支撑；对更强的模型，同一份内容可能压缩判断空间。评估这类机制时写明目标模型；需要同时服务强弱不同的模型时，把方法写成“默认做法 + 可以不用（说明即可）”，而不是强制步骤或只给边界。授权、机器契约与外部副作用不在此列，它们与模型强弱无关。

**2. `references/evidence-and-scale.md`「证据强度要匹配机制类型」一节**
> 行为证据要注明在哪个模型上取得。一个判断辅助在某个模型上有效，不能外推到更弱或更强的模型；当目标模型变化时，原先“需要行为验证”的结论要重新打开。

**3. `references/evidence-and-scale.md`「裁决强度」一节，第三等之后**
> 需要行为验证的结论，可以用一次性的、针对特定模型的对照来裁决：同一组真实任务，分别在有 / 无该机制（或新旧两版）下运行，比较结果与人工纠正次数。只在机制变化或目标模型变化时进行，不建立定期评测或自动优化循环。

## 不建议改的
- 不新增“档位”“模型等级”之类的配置或状态：模型相对性通过写法（默认 + 可以不用）解决，不需要额外的机制。
- 不改变“判断属于模型、硬控制只覆盖机器可判定的事物”的核心立场；本提案只是为它补上“对哪个模型而言”这一维。
